## Framing first

Two options the brief does not list sit between its poles, and one hidden assumption needs challenging:

- **0. Linkage-only record** (between 1 and 2): add `role`/`of` to `run.json` and a tester preamble variant — no guards, no refusals. This is the cheapest thing that fixes convention-only's real defect (nothing records that run 02 tests run 01, so audit and telemetry decay), while arbitration stays manual.
- **Semi-blind (contract-blind)**: tester gets the spec plus public API signatures, not bodies. Captures most of blind's independence at far less churn than full-blind.
- **Bite-gate the author's own tests** (half of 4, no second model): much of the validity gate's value — proving tests can fail — does not need a tester at all.
- Hidden assumption: "fixes go back to the same author session" is impossible today (`--resume` refuses a `done` run, `work/mod.rs:869`). Any pipeline design must either add a continue-with-new-instruction form or accept fresh runs per iteration (re-reading everything, cost, drift).

What would decide it: how often a cross-family test catches a bug that review + the author's own tests missed (run 01 found a real bug writing its own tests — but that is self-referential evidence), and whether the coordinator actually keeps running the second run manually once novelty fades.

**Q1.** Build the linkage layer (option 0), not enforcement. Convention-only loses the record: no linkage, no auditable decision trail, no aggregate view. Enforcement (path guard, family refusal, automated gate) can stay convention until live use shows a miss. Evidence that would change this: (a) any GLM work-run bug a second family's tests caught; (b) adherence decay of manual second runs; (c) tester cost per task on Muse vs gpt-6.1-sol.

**Q2.** Sighted over-fits: tests mirror the implementation, pass trivially, confirm the author's reading. Blind encodes the tester's own misreading of the spec and invents contracts the author never implemented — churn and "test bug" arbitrations. Blind wins where a crisp executable contract exists (CLI exit codes, record contents — this repo's contracts are of that kind); sighted fits bug fixes (the repro test is naturally blind: the bug is in base) and refactors (behavior must not change; over-fit risk is low and the point). Semi-blind is the better default for features.

**Q3.** The coordinator decides, always; c3 must never. Record for audit: the failing output verbatim, the exact command (`-j 2`), exit code, content hash of the test file at decision time (the `baseline_hashes` machinery exists), the revert-check outcome, and a `verdict` field only the coordinator writes. c3 helps without deciding: serial re-run (two runs disagree → flag flaky, not bug) and the revert-check.

**Q4.** Essential v1: `--role author|tests` + `--of <id>` linkage in `run.json`; a tester preamble; a **post-hoc** scope check (`files_changed` ⊆ declared scope → `scope_error`, non-zero exit). Gold-plating: family enforcement, automated validity gate, arbitration. A pre-run path guard is impossible on all three engines (acceptEdits has no path allowlist; codex sandbox is workspace-wide; muse unrestricted) — do not advertise containment. One-live-run is fine: the pipeline is sequential (author done → tester → author-fix as a new linked run); but note the `--resume`-refuses-`done` gap above. `#[cfg(test)]`: scope = `tests/**` plus brief-named files; inline `cfg(test)` edits are invisible to a path scope — say so, accept it. The gate's "fail on base" needs redefining: the tree is never committed and routinely dirty (run 01's baseline proves it), so it must be reverse-apply-the-patch in a scratch worktree, distinguishing compile-fail (weak) from assertion-fail, and costing two serialized full builds under the `-j 2`/OOM rule — keep it manual in v1, c3 records results.

**Q5.** GLM author + gpt-6.1-sol tester: strongest, but burns codex quota reviews need (the consult budget rule). GLM author + Muse tester: different family, near-free — the sensible default. DeepSeek-4.1-flash: low-stakes either side. GLM + GLM-flash: same family *and* same z.ai plan/quota — refuse that one outright. Otherwise warn, don't enforce: the roster has no family field, only label conventions.

**Q6.** Additions: (a) the sighted tester has nothing to read — `diff.txt` holds status+stat only and workers cannot run git; c3 must materialize a sanitized full patch (finding #1); (b) injection lands worst on a **muse** tester (unrestricted shell reading author content) — keep testers on the claude allow list (finding #7); (c) a quota-parked author blocks the tester (one live run) — pipeline latency doubles; (d) a weak tester produces biting-but-vacuous tests — the gate proves bite, not coverage; (e) the gate doubles Windows flake exposure; (f) work runs sit outside the consult ledger, so no pipeline-level telemetry exists today.
