- **F02-1** [minor] `crates/c3/src/budget/mod.rs:436` - The new z.ai quota GET builds a default ureq agent (follows up to 5 redirects) with `Authorization: Bearer <key>` attached, so a redirect from api.z.ai would be followed — unlike maintain/env.rs, which pins redirects(0) and re-targets by hand, same-site only, for keyless GETs; the wave's stated invariant is that a request carrying an API key never follows a redirect. Trigger: api.z.ai (or an intermediary) answering GET /api/monitor/usage/quota/limit with a 3xx to another host while the ZAI key is set. Evidence: read-code: Both build `ureq::AgentBuilder::new().timeout(HTTP_TIMEOUT).build()` with no redirects(0) and send the bearer token; contrast crates/c3/src/maintain/env.rs:122-157 which sets .redirects(0) and follows only keyless GETs, max 3 hops, same site.; assumed: Not verified whether ureq's default strips Authorization on cross-host redirects; the follow itself is certain. Verify: Inspect the vendored ureq 2.12.1 source (redirect_auth_headers default) or point the ZAI env key at a local server that 302s cross-host and observe whether the Authorization header arrives. Remedy: Build the agent with .redirects(0) (and treat a 3xx as no data) in zai_get and kimi_get, matching the maintain env policy.
- **F02-2** [minor] `crates/c3/src/maintain/mod.rs:507`, `crates/c3/src/maintain/mod.rs:581` - When the installed version cannot be parsed (`installed = None`, text "unknown"), the pass still updates and, on a post-update smoke failure, rolls back to the literal string "unknown" (npm install -g @openai/codex@unknown, grok update --version unknown), which cannot succeed — the engine is left on the version that failed its smoke although a rollback path existed. Trigger: A CLI whose `--version` output stops parsing (format change across versions is exactly when this happens) plus an available update whose post-update smoke fails. Evidence: read-code: The up-to-date check is inside `if let Some(inst) = installed`, so None falls through to update with installed_text="unknown"; do_rollback receives installed_text verbatim. - **F02-3** [minor] `crates/c3/src/maintain/mod.rs:624` - The model step ignores both the `--engine` filter and C3_MAINTAIN_SKIP: `c3 maintain --run --engine codex` still collects and swaps models of grok/agy/claude seats, editing the roster and spending smoke turns outside the scope the operator selected.
