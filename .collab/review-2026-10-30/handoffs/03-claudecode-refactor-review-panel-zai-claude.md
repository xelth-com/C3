## Q1 — `c3 finish` commit scope

Beyond the two known gate bugs, two more holes in the same gate:

- **Typechanges are never scanned.** `staged_text_paths` filters `--diff-filter=ACMR` (`crates/c3/src/finish/secret_gate.rs:105`); a staged `T` (symlink replaced by a regular file) carries new content but is excluded, so it commits unscanned while still appearing in the printed staged list (`git.rs:71`, no filter). See finding #1.
- **Fail-open on listing, distinct from the known per-diff fail-open.** If `git diff --cached --name-only` itself fails, `staged_text_paths` returns `Vec::new()` (`secret_gate.rs:109-116`) and the gate reports clean over zero files. See finding #2.
- Binary skip: any blob with a NUL in the first 8 KiB is skipped (`secret_gate.rs:50-54`) — a secret placed after binary-looking padding passes (note, finding #8).
- "Added lines only" is otherwise a sound trade-off: a pure `R100` rename or mode-only change introduces no content, and `.eck/lastsnapshot` output written pre-stage (`finish/mod.rs:177-187`) IS staged and scanned. The never-commit matcher (`never_commit.rs:48-71`) parses `-z` correctly, skips rename origins, and `repo_root` comes from `rev-parse --show-toplevel` with a cwd fallback that makes `add -A` fail loudly outside a repo — no outside-repo staging path found.

- **F03-2** [major] `crates/c3/src/finish/secret_gate.rs:115` - The gate fail-opens on a failure to LIST staged files (distinct from the already-known per-file diff fail-open): a non-success `git diff --cached --name-only` yields an empty path list, `scan_staged` returns no hits, and the commit proceeds as clean. Trigger: The `git diff --cached --name-only ... -z` subprocess fails (broken index, lock contention, git error) during `c3 finish`. Evidence: read-code: `match out { Ok(o) if o.status.success() => ...collect(), _ => Vec::new() }` — the error arm silently produces an empty list.; read-code: `scan_staged`'s empty result is treated as clean and the flow continues to commit. Verify: Make the listing command fail (e.g. GIT_INDEX_FILE pointing at a corrupt index) in a test harness and confirm `c3 finish` commits instead of refusing.
