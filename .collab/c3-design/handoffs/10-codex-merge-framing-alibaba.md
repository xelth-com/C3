# C3 merge framing

## Framing challenge (before the answers)
1. `Store` with `files`+`surreal` impls (handoff:56) contradicts "files = record, DB rebuildable" (handoff:63): interchangeable impls assert the DB *can* be the record. Use two types — `RecordStore` (one impl: files) and `Index` (impls `surreal`, **`none`**). `none` is the unlisted, load-bearing option: DB features degrade instead of fail, CI skips SurrealKV, light/heavy becomes a runtime fact, not a feature-flag argument.
2. A third tier is missing: **Recipe**. Snapshots, packs and the DB are derived; commit the claim+focus+budget+anchor+router config that reproduces them. eckSnapshot already does this (gitignores `.eck/snapshots/`, commits `anchor`/`update_seq`) — generalize it.

## Q1
Split is right; don't make the DB the truth. What breaks: (a) **lock ownership** — R12 detach + `c3-mcp` + a foreground CLI = three processes per repo, and embedded SurrealKV is single-process (`xelth.rs/src/main.rs:154`); (b) **recovery** — files survive a crash via the plugin's atomic write order + `.consult.write.lock`, a half-written KV does not; (c) **two tools, one repo** — C3's `.gitignore` already ignores `.consult.lock`/`.consult.write.lock`, so C3 must honor those names, not invent new ones. Rule: the `.consult.lock` holder is the only DB writer; everyone else opens read-only or skips indexing; a DB failure never fails a consultation.

## Q2
Thompson over Beta is wrong at n≈tens: `verified`/`rejected` labels arrive days late, `HIT%` is null when both counts are zero, and the draw itself assigns hard briefs → propensity confounding. Ship shrunk-hit-rate **softmax + epsilon** with `router_version`/`policy` fields; log propensities and seed so off-policy evaluation — and a later Thompson switch — needs no schema change. Similarity: **BM25 over stored briefs only** (no embeddings), `-Topic` as hard override; the router must not depend on HNSW. Auditability: `seed = sha256(task‖brief_sha‖purpose‖roster_version‖router_version)`; record the *post-filter* probability vector **and** the pre-filter availability set, because R15 filters availability before the draw.

## Q3
Layers, not a choice: named levels are presets that **expand** to `(k, effort/word caps, wall+token budget)`, and the expansion — never the level name — lands in the ledger. Reuse R14's numbers so there is one vocabulary; `--panel k` and `--budget` override. Unlisted option: **escalation** — one cheap reviewer first, widen only on HOLD/REJECT or a blocker. ## Verdict: ADVISE

The files-as-record / DB-as-index split is right, but the `Store` trait contradicts it, the embedded-DB lock model is undefined under R12+MCP concurrency, and the explainer pack is a publication artifact with an unredacted code path — all cheap to fix now and expensive later.

### Blockers

- **F10-1** `.collab/c3-design/handoffs/01-claude-merge-framing.md:56`, `.collab/c3-design/handoffs/01-claude-merge-framing.md:63` - The proposal makes embedded SurrealKV a `Store` implementation but defines no process-ownership or lock model, while R12 detach, a long-lived `c3-mcp` server and a foreground CLI can all touch one repository's DB at the same time; embedded SurrealKV is opened as a single-process on-disk engine, so concurrent C3 processes on one repo have undefined behaviour (open failure, blocking, or corruption of the index). Verify: Run RC1: hold `.eck/db` open with `xelth mcp` and open the same directory from a second process; observe error, block, or corruption. Remedy: Declare the DB a derived cache with a single writer: only the `.consult.lock` holder opens it read-write; every other process opens read-only or skips indexing. Add `Index: none` so a lock failure degrades to 'no index this run' and never fails a consultation. Rebuild = reindex from files + repo.
- **F10-2** `.collab/c3-design/handoffs/01-claude-merge-framing.md:74` - The explainer pack is a publication artifact that embeds source into a file a human pastes into a third-party chat, but the redaction precedent C3 is porting only redacts in one command's output path, and the OpenRouter key-loading precedent falls back to a repo `.env` — so a secret can be embedded and shipped off-machine, with no consent or license gate.
