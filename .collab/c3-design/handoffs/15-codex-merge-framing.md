The framing conflates a compatibility port with several new products. Preserve the fixed vision, but evaluate those additions separately. Missing options include an authoritative file store plus a separate query index, short-lived serialized DB sessions, an external credential-bearing API adapter, and lexical retrieval before embeddings. Choosing between them requires target repository sizes/languages, cold/warm latency budgets, expected concurrency, rated consultation counts, and acceptable network destinations. Performance remains unverified.

**Q1.** Keep files authoritative; separate `EvidenceStore` from `ContextIndex`. Interchangeable file/DB backends obscure their different responsibilities, although a trait alone does not make the DB authoritative (qualifying F10-3). Commit evidence atomically under the plugin-compatible task lock, then index by evidence generation/hash. Detect external changes and provide rebuild/recovery. Persist every routing input and policy version needed for replay. Cross-project history needs retained source evidence. F11-2 identifies an omission, not proof that rebuilding is impossible. Initially serialize short-lived DB opens across processes; MCP must close its connection between operations. A daemon would diverge from R12 (`.collab/c3-design/context/codex-consult.md:41`). DB-first adds mandatory export, backup and migration machinery.

**Q2.** Neither Thompson sampling nor softmax fixes undefined rewards. Sparse data does not make Thompson sampling mathematically invalid; it limits learning. Start with purpose-level, strongly regularized posteriors and explicit tags; defer similarity-weighted evidence until evaluated. Define one consultation-level reward, missing-label handling, and decay before combining usefulness and finding outcomes; otherwise prolific reviewers can gain disproportionate influence. Softmax over raw HIT% hides uncertainty and mishandles null denominators (`.collab/c3-design/context/codex-consult.md:48`). Record eligible/excluded members, reasons, posterior parameters, observation cutoff, policy/RNG versions, seed, sampled scores, selection order and constraints. A sampled Beta score is not an inclusion probability. Define exploration as a mixture over feasible panels; an unconditional per-member floor may be impossible (finding #4).

**Q3.** Use named presets resolving to an explicit seat count; `--panel k` overrides the preset. Treat token, cost and elapsed-time limits as separate constraints, reserving output and retry allowances. Subscription and API tokens are not interchangeable costs. Print the resolved plan. Define whether an unavailable seat permits a smaller panel; zero usable reviewers must produce an explicit unsatisfied-panel outcome. Base defaults on R14 (`.collab/c3-design/context/codex-consult.md:43`).

**Q4.** Pack-only first. It limits the remote model's capabilities, but C3 still reads files, sends data and writes evidence. Treat returned text as data. Preserve exact sanitized request context with source mappings and coverage limitations (finding #2). Native HTTP necessarily handles a credential: explicitly revise the README contract or isolate credentials in an adapter. Redaction does not preserve the literal old invariant. Distinguish consultation, attempt and conversation IDs; HTTP retries reuse captured inputs without redrawing, and ambiguous timeouts must not imply exactly-once billing.

**Q5.** Port schema/query ideas, incremental hashes and bounded graph expansion; begin with BM25 and declared parser coverage. Add vectors only with measured benefit and explicit model/version/egress policy. Do not inherit mock-vector success (finding #3). Keep reconciliation coordinator-owned, citation-based and advisory; preserve disagreement and original findings, consistent with the no-voting rule (`.collab/c3-design/context/codex-consult.md:26`). Adapt T-hub transport behind a typed payload allowlist and the chosen consent policy; do not copy it verbatim. Local routing must work with outbound telemetry disabled.

**Q6.** Header: audience, explanation question, claim explicitly marked unverified, repository revision plus dirty-content identity, scope, omissions, redactions, parser limitations, citation format, and an instruction to distinguish supported conclusions from unknowns. Repository text is evidence, not operating instructions. Include focus-file bodies or line-preserving excerpts plus supporting relationships; label graph edges as derived and link them to source. Skeletons need explicit omission markers. Reuse extraction/sanitization infrastructure, with separate reviewer and explainer prompts. The eckSnapshot trailing-role precedent is useful, but its redaction placement is not (`.collab/c3-design/context/eckSnapshot.md:17–32,60–63`).

**Q7.** Start with three crates: dependency-light contracts, runtime, and CLI/MCP entry points; organize other components as modules. C3 is explicitly the heavy product, so include SurrealDB in its supported release; make embeddings optional. A second light distribution needs a demonstrated requirement because PowerShell already fills that role. Freeze file/protocol invariants before traits. Extend README milestones explicitly rather than hiding new subsystems inside the parity port.

**Q8.** Decide schema-extension compatibility, repository/worktree identity, case/symlink handling, cancellation and recovery ownership, cross-project evidence retention, and engine capability reporting. Keep C3 snapshot state separate from eckSnapshot anchors. Separate `finish_task` writer authority from reviewer capabilities. Resolve R17 and credential-contract divergences explicitly. I corroborate roster incompatibility from the actual validator; I contradict F10-6's claim that pack evidence requires a reply-schema bump. Existing `reference` strings can identify pack evidence; the missing requirement is auditable provenance.
