## Framing first

The brief's own pass-2 evidence undercuts the premise: F91-1 and F91-3 are "the fix closed the simple case, this is the remaining case" — a **verification gap**, not a design gap. Astra's one-sentence remedies were adequate directions; what was missing is that nobody executed Astra's own RC1–RC3 fixtures between passes. Options the brief does not list:

- **O1: test-first worker briefs.** The worker must write a failing test that drives the finding's trigger *before* the fix, and the next acceptance pass runs it. Cost: zero extra consultations.
- **O2: the finder's `remedy` becomes acceptance criteria.** The finder already wrote RC1–RC3; the coordinator can turn those into the worker's definition of done instead of paying three solvers.
- **O3: remedy panel as proposed.** Pays ~3 consultations per blocker for design diversity.

To choose I would need: the per-release window budget vs. deadline, and whether the roster workers can run `cargo test` in-tree (O1/O2 need it; O3 does not). My recommendation: O1+O2 by default, O3 only when two consecutive passes fail the *same* finding — i.e., escalate to solvers on demonstrated design failure, not on every blocker.

## Q1. Roles

Sound, with the verifier being **a shipped test, then the finder**. The solver must ship the test that drives the trigger; the finder verifies on the next pass against criteria it stated when raising the finding. Failure modes: (a) solver ignorant of the codebase — mitigated by the pack of located code plus nearest existing tests; (b) finder rejecting every foreign fix — mitigated by requiring the finder to state acceptance criteria up front, so a rejection must cite a failed criterion or a *new* trigger (a new trigger is a new finding, credited as such, not a veto); (c) cost — gate remedy panels on blockers only, and batch same-file findings into one remedy consultation.

## Q2. Minimal record and workflow

`findings[].proposals[]` = `{proposer, approach, locations, patch_sketch, test, risks, confidence, status: proposed|adopted|rejected, reason}` — one JSON object per proposal inside the existing `findings.json`; nothing else new. Purpose `remedy`, preset effort high, `--exclude-vendor <finder lab>`, pack = the finding record + located files + the tests that exist. The coordinator records adoption by setting `status`+`reason`. Never automate: the adoption choice, the decision to spend the window (the `--remedy` line is offered, not run), and the `verified` flip (finder-only).

## Q4. Scoring

Credit the solver only on `adopted` **and** `verified` (adoption alone is coordinator taste; verification is ground truth). Credit the finder for the finding itself, not for the fix — otherwise finder and solver incentives couple. This makes "good solver" mean "fixes stay closed", which is exactly what passes 1–2 lacked.
