Review for security: what an attacker, a malicious input or a careless caller can make this code
do. Look at trust boundaries, untrusted input reaching paths, commands, queries or templates,
secrets and credentials (where they are read, logged, stored or sent), permissions and sandboxing,
injection, path traversal, unsafe defaults and failure modes that fail open. For each finding name
the attacker's input or position, the impact and the smallest fix.
